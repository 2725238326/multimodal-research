## 0. 规划前提：本轮实测的约束

规划必须建立在实测约束上，而不是假设上。本轮核实了三组事实。

### 0.1 网络可达性（决定所有外部资产路线）

| 可达 | 不可达 |
| --- | --- |
| `api.github.com`、`hf-mirror.com`、`arxiv.org`、`openaccess.thecvf.com`、`data.csail.mit.edu`、`zenodo.org`、`pan.baidu.com` | `github.com`、`huggingface.co`、`drive.google.com`、`www.dropbox.com`、`figshare.com` |

`raw.githubusercontent.com` 表现不稳定：本轮先成功取回 SGNet README，随后返回连接重置，属间歇可用而非阻断。

这直接决定：**Google Drive 上的官方 SGNet 权重与 SGNet 版 NYU-v2 在本机无法取得**，而 hf-mirror、Zenodo、百度网盘上的资产可以取得。

### 0.2 SGNet 权重没有可用镜像

在 hf-mirror 上检索 `SGNet`、`C2PD`、`depth super resolution guided`：`C2PD` 与 depth-SR 查询均无结果；`SGNet` 仅有 `glennliu/sgnet`（3 次下载），与 `yanzq95/SGNet` 无关。**权重镜像路线排除。**

### 0.3 文献库中已有一个直接相关的候选数据集

`literature/paper-index.md` 第 71 行已收录 **ICTPolarReal**（CVPR 2026），描述为"偏振、漫/镜面反射和多光照真值；可支撑反射响应与材质属性验证"。

这同时命中两个当前缺口：它是第五轮审计中被判为"本数据集不可得"的**偏振观测量**，也可能充当负结果论文所缺的**第二数据集**。其可得性与许可尚未核验，是本规划中优先级最高的待验证项。

## 1. 对现有证据的诚实复核

在设计后续工作前，先复核已有结论是否经得起审稿。发现两处必须修正的地方。

### 1.1 需要修正：「权衡」框架不严谨，实为「支配」关系

综述稿把统一发现表述为稳定性—辨识性权衡。对已提交的 `results/quantitative/material_response_probe_v0/summary.json` 中全部 10 个条件，在（区域准确率↑，翻转率↓）平面上重算 Pareto 支配关系：

| 条件 | 区域准确率 | 宏准确率 | 翻转率 | 状态 |
| --- | ---: | ---: | ---: | --- |
| 单帧 RGB | 69.70% | 69.16% | 61.11% | **前沿**（准确率最优） |
| 等参数分支（对照） | 69.70% | 69.16% | 61.11% | **前沿**（与单帧 RGB 完全并列） |
| 多光照均值 | 66.67% | 63.46% | 0.00% | **前沿**（稳定性最优） |
| 均值 + 方差 | 66.67% | 63.15% | 23.23% | 被支配 |
| Pairwise response | 64.65% | 61.29% | 29.80% | 被支配 |
| RGB + albedo 拼接 | 58.59% | 53.47% | 63.64% | 被支配 |
| RGB + albedo 残差 | 62.63% | 61.05% | 67.68% | 被支配 |
| 随机残差（对照） | 63.13% | 59.88% | 64.14% | 被支配 |
| 错误区域 albedo（对照） | 46.97% | 45.41% | 55.56% | 被支配 |
| 打乱光照对（对照） | 42.42% | 39.89% | 57.07% | 被支配 |

**10 个条件中 8 个被支配。** 非支配集只有三项：单帧 RGB、与之完全并列的等参数对照，以及朴素平均。所有比朴素平均更精细的响应构造——均值+方差、pairwise response、albedo 拼接与残差——**在两个轴上都不优于**朴素平均：均值+方差准确率持平、宏准确率略低（63.15% 对 63.46%）而稳定性明显更差；pairwise response 两轴皆差。

这不是权衡曲线，而是支配关系。而且**更强的表述反而更容易守住**：

> 在简单平均之上叠加响应结构，两个指标同时变差。精心设计的跨光照响应描述符被朴素平均严格支配。

一个真正的权衡会被审稿人视为正常的工程取舍；而"更精细的方法被最朴素的基线支配"是明确的负结果。综述稿第 4 节必须按此重写。

### 1.2 需要补证：双分支 oracle 上限 77.27% 目前不在 Git 内

`docs/worknow.md` 记录：光度分支与旧 sample-majority RGB 逐区域配对后，二者的 oracle 三次均为 **77.27%**，相对 RGB 单独的 69.70% 有 7.57 pp 余量，同时存在 4–7 个纠错与 5–6 个破坏。

若该数字成立，它显著改变结论的表述：不是"响应不携带信息"，而是**"响应携带互补信息，但没有任何被测选择器能够取用它"**。这更精确，也解释了第三轮（选择性拒判）为什么是正确的假设、其失败为什么重要。

但该数字来自远端完整摘要（SHA `7dab129c…`），**未进入 Git**，committed summary 里没有 oracle 字段。写进论文前必须重新导出并提交聚合值。

### 1.3 最大的审稿漏洞：容量混淆

第二轮的浅层接口固定为"至多 32 个 train-only PCA 分量 + L2 logistic，无超参搜索"。审稿人会问：

> 响应特征维度更高，你用固定的低容量头，怎么排除"不是特征没用，而是接口取不出来"？

现有的等容量 RGB 对照只证明了"给 RGB 更多参数也不会更好"，**没有证明"给 response 更多容量仍然无效"**。这是当前最容易被推翻的一环。

需要说明的是，第四轮的外部确认结论**不受此攻击影响**：那里的失败是迁移失败，且打乱（39.58%）与 exposure-only（36.25%）**高于**主方法（30.83%），属于对照超越主方法，与容量无关。所以证据链的最强一环是完好的，被攻击的是第二轮。

## 2. 三条路线的设计

### 路线 A：把负结果做成可投稿的工作

**可守住的 claim**（已按 1.1–1.3 收窄）：

> 在冻结视觉编码器与固定浅层接口下，多光照响应特征相对单帧 RGB 无可迁移增益：精细响应描述符被朴素平均支配；在官方零重叠 test split 上显著有害并被打乱/曝光对照超越；且在标定 HDR 与实测光探针下，所需的逐表面辐照度归一化在该采集设置下不可定义。

| 编号 | 工作项 | 成本 | 阻塞 | 作用 |
| --- | --- | --- | --- | --- |
| A1 | 支配关系重分析，重写综述稿第 4 节，产出 (准确率, 翻转率) 平面图与 Pareto 前沿 | 极低，纯重分析 | 无 | 修正 1.1 |
| A2 | 重新导出双分支 oracle 上限并提交聚合值 | 低，远端已有缓存 | 无 | 补 1.2 |
| A3 | 容量消融：同一 response 特征扫 PCA 分量 {8,16,32,64,128,全维} × head {logistic, 单隐层 MLP} | 低，330 样本、特征已缓存，分钟级 | **需用户裁定，见 4.1** | 堵 1.3 |
| A4 | 任务上限 oracle：给定 5 个光照的完美选择，材质分类天花板是多少 | 低 | 无 | 区分"方法无效"与"任务本身难" |
| A5 | 第二数据集外部效度 | 中—高 | 依赖 ICTPolarReal 可得性 | 外部效度 |
| A6 | 英文重写 | 中 | 无 | 投稿必需 |

A1、A2、A4 无阻塞且成本低，应立即执行。A3 是性价比最高的一项，但触及既定禁令边界。A5 依赖路线 C 的核查结果。

**投稿定位**：严谨负结果 + 方法论案例。第四轮（开发集 +5.56 pp、方向一致、控制合理，但外部确认 −12.50 pp）本身就是一个"若不做零重叠外部确认就会得出假阳性"的完整案例。接收此类工作的场所包括 TMLR 等明确接受负结果的期刊，以及各主会的 negative-results / reproducibility 类工作坊；具体投稿目标需要在确认当期征稿后再定，本规划不臆断。

### 路线 B：SGNet/RGB-D-D 解阻塞

两个阻塞相互独立，必须分别处理。

**阻塞 1 — 官方权重（Google Drive 不可达）**

| 方案 | 可行性 | 代价 |
| --- | --- | --- |
| B1a 换一台能访问 Drive 的机器本地下载，哈希后上传 | 最合规，完全符合现有规则 | 需要一台可访问 Drive 的机器 |
| B1b 显式放宽"服务器不得下载"限制 | 可行但需写入决策记录 | 破坏现有资产治理边界，需明确授权 |
| B1c 找镜像 | **已排除**，hf-mirror 无对应权重 | — |
| B1d 放弃预训练权重、自行训练 | **死路**：训练同样需要拿不到的 NYU-v2/RGB-D-D | — |

**阻塞 2 — RGB-D-D 数据授权**

需正式员工签署 Release Agreement 并用机构邮箱登记。一个尚未核查的有利事实：该数据集出自国内课题组，而 `pan.baidu.com` 在本机可达；若其分发走百度网盘，则**授权一旦取得，取数路径是通的**。这是一个低成本可执行的核查（B2）。

**结论**：路线 B 的启动条件是 B1a 或 B1b 二选一，**加上**授权到位。在此之前只能停留在静态审计，任何"先跑起来看看"的尝试都会撞上这两堵墙。

### 路线 C：偏振观测量（最高上限）

第五轮的结论是"Multi-Illumination 内不存在能改变可观测证据的路线"，这个结论在该数据集内成立。ICTPolarReal 提供的是**另一个数据集**上的偏振观测量，因此不违反 `D-017`／`D-018`——它恰恰满足了那两条决策要求的"引入不同的可观测证据"。

| 编号 | 工作项 | 成本 | 说明 |
| --- | --- | --- | --- |
| C1 | 核查 ICTPolarReal 的官方来源、许可、下载方式与规模 | 低 | 论文页在 CVF（可达）；先读论文确认数据构成与获取方式 |
| C2 | 若可得：按第五轮同一方法做零训练 oracle gate | 低—中 | 偏振度/偏振角能否分离材质，用官方标注区域、0 训练参数检验 |
| C3 | 若 C2 通过：预注册确认性实验 | 中 | 此时才允许训练 |

**关键设计**：C2 必须复用第五轮的方法学——零训练参数、官方 mask 区域、between/within 判别力比、场景为独立单元。第五轮以 6 个场景、0 个训练参数的成本否决了一整条路线，这是本项目性价比最高的工具，应当在任何新方向上首先使用。

## 3. 推荐排序

按"是否被外部因素阻塞"排序，而非按吸引力排序：

1. **立即执行、无阻塞**：A1（支配关系重分析）、A2（oracle 上限补证）、A4（任务天花板）。三项都是纯重分析或远端已有缓存的低成本计算，能显著提高负结果的可辩护性。
2. **并行的低成本核查**：C1（ICTPolarReal 可得性）、B2（RGB-D-D 是否走百度网盘）。两项都是读官方来源，几十分钟内可给出确定答案，且各自决定一整条路线是否存在。
3. **需要用户裁定后执行**：A3（容量消融）。
4. **需要用户行动后才能启动**：路线 B 全部。
5. **依赖 C1 结果**：A5、C2、C3。

理由：路线 A 是唯一完全在我们控制之内的产出路径，把已投入的成本转化为成果；路线 C 上限最高但可得性未知，而核查成本极低，应当尽快消除不确定性；路线 B 的阻塞不在技术侧，继续投入执行者时间不会推进。

## 4. 需要决策的事项

### 4.1 容量消融是否越界

既定禁令为"不得在当前 LDR response 数据上继续调 descriptor、crop、threshold、LoRA、BRDF deep head、conflict verifier 或蒸馏"。

A3 与被禁行为的区别在于目的与停止规则：它的目的是**证伪**——预先声明"若任何容量下 response 都不优于 RGB，则容量混淆被排除；若某个容量下 response 反超，则第二轮结论作废并需重新预注册"。它不是在寻找可用增益，而是在为负结论排除替代解释，且无论结果如何都不会导致训练扩展。

但它确实在同一批 LDR response 数据上再次拟合模型，形式上贴近禁令边界。请裁定是否放行。若不放行，综述稿必须在限制一节明确写出"容量混淆未被排除"，claim 相应收窄到"在本文使用的固定浅层接口下"。

### 4.2 路线 B 的解阻塞方式

B1a（换机器）还是 B1b（放宽服务器下载限制）？前者合规但需要设备，后者需要写入决策记录并明确适用范围（仅限官方公开资产、仅限本次、必须留存哈希）。

### 4.3 论文语言与目标

综述稿现为中文。是否立即启动英文重写（A6），还是先完成 A1–A4 把内容定稿再翻译？建议后者，避免翻译已知要改的章节。

## 5. 本规划不做的事

- 不在 A3 裁定前运行任何模型拟合。
- 不在 C1 完成前假设 ICTPolarReal 可用，也不据此修改任何既有结论。
- 不代替用户签署或登记任何数据授权。
- 不因为路线 B 受阻而降低其证据标准，或把上游聚合结果称为本 fork 复现。
