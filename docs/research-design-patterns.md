# 科研设计模式库

**版本：1.0**  
**日期：2026-07-21**  
**状态：Completed（流程规范）；具体研究方向仍需单独预注册**

## 1. 目的

科研设计模式是对反复出现的研究矛盾给出的可复用解决结构。它不等于具体网络模块，也不自动构成论文创新。每个新方向都应说明：

- 当前上下文与可证伪问题；
- 使用了哪些模式；
- 为什么这些模式适合当前矛盾；
- 对应的反模式与失败条件；
- 最小验证单元和退出标准。

模式只组织推理和证据，不替代数据、实验和统计。

## 2. 统一模式卡

每个模式或跨领域机制迁移按以下字段记录：

| 字段 | 要回答的问题 |
| --- | --- |
| Context | 在什么数据、任务和失败下使用？ |
| Tension | 哪两个目标或证据发生冲突？ |
| Forces | 数据、模型、成本、许可和部署有哪些约束？ |
| Structure | 用什么角色和信息流解决？ |
| Minimal gate | 最便宜的可证伪实验是什么？ |
| Controls | 哪些负对照能排除捷径？ |
| Go / No-Go | 运行前的数值门槛是什么？ |
| Artifacts | 计划、配置、日志、汇总和决策存在哪里？ |
| Collision | 最近工作已覆盖了哪些部分？剩余差异是什么？ |

## 3. 核心科研模式

### RP-01 可证伪研究合同

**Context**：任何需要运行新实验的假设。  
**Tension**：探索需要灵活，但结论需要在看结果前固定判断标准。  
**Structure**：

1. 写出一句可被证伪的假设；
2. 指定独立统计单元、主指标和保护指标；
3. 写出 Go、No-Go、资源上限和允许偏差；
4. 将计划冻结后再运行。

**Minimal gate**：计划能否在不看结果的情况下明确区分成功、失败和不确定。  
**反模式**：`Metric Shopping`、结果出来后改主指标、只记录支持证据。

### RP-02 证据阶梯

**Context**：昂贵模型、数据或系统方案。  
**Tension**：最终系统最接近目标，但最难定位失败原因。  
**Structure**：

```text
许可/字段审计
  → Oracle gate
  → Frozen-feature probe
  → 小头/轻量适配
  → 受控训练
  → 外部数据
  → VLM/agent 系统
```

上一层没有通过，不进入下一层。  
**反模式**：一开始训练大模型、用系统结果掩盖底层证据无效。

### RP-03 最强简单基线锚

**Context**：新增复杂模块、额外模态、agent 或生成模型。  
**Tension**：复杂系统可能只是增加参数、样本或测试时计算。  
**Structure**：先建立同数据、同容量、同预算的最强简单基线；新增机制必须解释超出基线的增益。  
**Controls**：随机额外输入、等参数 MLP、相同次数的测试增强、规则程序。  
**反模式**：只比较旧弱基线、不给等计算预算对照。

### RP-04 单机制增量

**Context**：同时存在数据、提示、模型和输入变化。  
**Tension**：快速组合容易得到效果，但无法知道效果来自哪里。  
**Structure**：一个确认性实验只改变一个机制；组合效果用析因设计或分阶段消融。  
**Minimal gate**：结果表能否把每一个 claim 映射到唯一实验差异。  
**反模式**：`Kitchen Sink` 模块堆叠。

### RP-05 反事实控制四件套

**Context**：提示、辅助模态、外部知识、物理证据或 agent 工具调用。  
**Structure**：至少比较：

1. 正确且相关的证据；
2. 错误或反向证据；
3. 打乱样本/区域后的证据；
4. 信息量相近但无关的证据。

正确证据的收益必须显著高于后三者，并呈现合理方向。  
**反模式**：只比较“有输入”和“无输入”，无法排除更多 token、更多像素或答案泄漏。

### RP-06 训练期特权教师—部署期学生

**Context**：训练时可获得多光照、albedo、depth、radar、touch 或多个模型，部署时只有 RGB。  
**Tension**：辅助模态含互补证据，但推理成本或可用性不允许保留。  
**Structure**：

- teacher 使用丰富模态；
- student 只使用部署时输入；
- teacher 必须先独立证明更准且更稳；
- 只在 teacher 可靠时蒸馏；
- 记录 teacher/student 模态差距和冲突。

**反模式**：弱 teacher 全量蒸馏、训练/测试输入条件不透明。

### RP-07 语义提案—物理验证

**Context**：目标是深度、材质、接触、支撑、硬度等物理量，但语义能缩小候选空间。  
**Tension**：语义擅长提出“可能是什么”，却容易把类别共现误当物理测量。  
**Structure**：

```text
VLM/语义编码器 → 候选、区域、属性假设
物理分支       → 深度/几何/反射/雷达/触觉证据
冲突模块       → 校准、拒答、重新测量或否决
```

物理测量对物理 claim 有最终否决权；语义不得作为未观测物理真值。  
**Minimal gate**：物理验证器能否纠正语义先验故意制造的错误候选。  
**反模式**：`Semantic Truth Substitution`，例如根据“桌子通常是木头”直接输出材质。

### RP-08 不变—响应因子化

**Context**：观测随光照、视角、传感器或环境变化，但变化本身也含任务信息。  
**Tension**：完全不变会丢掉高光、透明、粗糙度等判别线索；完全保留又会造成域漂移。  
**Structure**：

- invariant branch 学习身份稳定部分；
- response/equivariant branch 学习受控变化规律；
- 用去相关或正交约束避免两分支坍缩；
- 由任务/样本级路由器决定证据权重。

**Controls**：打乱光照配对、错误区域、删除 residual、只做一致性训练。  
**反模式**：把所有变化都当噪声压平。

### RP-09 质量与冲突感知路由

**Context**：不同模态或专家在不同样本上强弱互换。  
**Structure**：

- 每个分支输出预测、质量分数和不确定性；
- 路由器依据可观测质量而非最终标签选择；
- 报告路由准确率、冲突子集性能和校准；
- 保留拒答或回退路径。

**Minimal gate**：oracle router 的上限是否明显高于固定融合；若没有上限，不训练路由器。  
**反模式**：固定拼接、无约束 attention、只报告平均精度。

### RP-10 结构先于语义密集化

**Context**：区域、边界、3D 组件或局部材质推理。  
**Tension**：CLIP/VLM 语义强但空间粗；DINO/depth/segmentation 空间细但语言弱。  
**Structure**：先用 dense visual/geometry prior 建结构单元，再在少量高质量区域查询语义，最后按结构聚合。  
**Controls**：随机区域、低质量视图、dense CLIP 插值、无结构聚合。  
**反模式**：在所有像素/点上盲目复制稀疏语义特征。

### RP-11 主动干预 Agent

**Context**：静态观测不足，但系统可以选择下一次测量、光照、视角或工具。  
**Tension**：agent 可能只是昂贵的固定流水线。  
**Structure**：

- 状态是当前假设和不确定性；
- 动作是可验证的测量/工具调用；
- 奖励是信息增益、任务成功和成本；
- 设置最大步数与安全回退；
- 与固定顺序、随机策略和 oracle 策略比较。

**反模式**：让 agent 重复询问同一模型后多数投票；无执行式指标。

### RP-12 可复现实验胶囊

**Context**：任何形成 claim 的实验。  
**Structure**：

- commit、配置 hash、manifest hash、模型 revision；
- 环境、设备、种子、命令和退出码；
- 输入/解析/指标 smoke test；
- 脱敏聚合摘要和 claim-to-evidence 映射；
- 独立执行者可在小样本上复跑。

**反模式**：只有 notebook、聊天记录或手工结果表。

## 4. 跨领域机制迁移模式

其他方向的技术可以尝试，但必须先填写“机制迁移卡”：

```text
来源领域：
原方法解决的矛盾：
被迁移的是机制还是实现：
本任务中的对应变量：
不成立的原假设：
最近工作碰撞：
最简单本地基线：
错误/反向/打乱控制：
1–2 天 No-Go 条件：
```

允许迁移：

- 信息流结构；
- 损失设计背后的约束；
- 训练/部署模态分离；
- 质量估计、路由和主动测量；
- 统计设计与评估协议。

不能直接迁移：

- 其他任务的标签含义；
- 未核验的数据许可和预处理；
- 只在原数据成立的模型结论；
- 不满足本任务可观测性的物理假设。

## 5. 多方向组合模式

项目使用“一主线、两邻接、一高风险”的 WIP 上限：

| 槽位 | 数量 | 允许工作 | 晋级条件 |
| --- | ---: | --- | --- |
| 主线 | 1 | 完整计划、复现和确认性实验 | 已有本仓库失败证据与明确论文 claim |
| 邻接 gate | 最多 2 | 数据审计、oracle、frozen probe | 1–2 天内能明确 Go/No-Go |
| 高风险探索 | 最多 1 | 小型概念验证 | 有独立真值和强负对照 |
| 候选池 | 不限 | 文献卡和机制迁移卡 | 不占训练资源 |

建议资源比例为主线 60%、邻接 gate 25%、复现/治理 15%。高风险探索从邻接预算中竞争，不额外扩张。

方向之间只有满足以下任一条件才允许组合：

1. 一个模块修复另一个模块已经观察到的失败；
2. 两者提供可测量的互补证据；
3. 组合能生成单模块无法提出的新可证伪 claim。

“都可能有用”不是组合理由。

## 6. 探索与确认分轨

| 项目 | Exploratory | Confirmatory |
| --- | --- | --- |
| 目的 | 发现效应、排查接口 | 检验冻结假设 |
| 数据 | 可用开发集 | 预先冻结的验证/测试集 |
| 指标 | 可多看，但标为探索 | 主指标和统计方法固定 |
| 提示/超参 | 可迭代并完整记录 | 不根据测试结果修改 |
| 结论 | 生成假设 | 支持/不支持 claim |

探索结果不得直接升级为稳定结论；必须建立新的确认性计划。

## 7. 模式选择快速表

| 观察到的问题 | 首选模式 |
| --- | --- |
| 辅助模态整体弱、局部有用 | RP-06 + RP-09 |
| 稳定性提高但准确率下降 | RP-08 |
| VLM 会猜类别但物理值不可靠 | RP-07 |
| CLIP 空间边界粗或跨视图噪声大 | RP-10 |
| 只有系统组合有效，原因不明 | RP-03 + RP-04 |
| 提示加入后提升，担心泄漏 | RP-05 |
| 单次观测本身不可辨识 | RP-11 |
| 新领域方法看起来可借 | 机制迁移卡 + RP-02 |

## 8. 方法学依据与使用边界

- [NIST/SEMATECH Engineering Statistics Handbook](https://www.itl.nist.gov/div898/handbook/) 提供实验设计、建模和过程改进的工程统计框架；本库将其“先定义目标、因素、响应和设计”的原则落成 RP-01、RP-03 和 RP-04。
- [Nature Registered Reports](https://www.nature.com/nature/for-authors/registered-reports) 将方法与分析计划放在结果之前审查；本库借鉴的是预注册和探索/确认分轨原则，不表示本项目已经注册研究。
- [ACM Artifact Review and Badging](https://www.acm.org/publications/policies/artifact-review-and-badging-current) 区分可获得、可复现和可复用等证据层级；RP-12 将其转化为适合本仓库的实验胶囊要求，不自行宣称获得徽章。

这些来源约束研究过程，不替代具体任务论文的结论级查新。新方向仍须在运行前完成碰撞检查和本地最小 gate。
